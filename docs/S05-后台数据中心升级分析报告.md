## 三、缺失功能分析（对照 S05 目标）

### 3.1 用户活动中心

| 目标行为 | 现状 | 缺失 |
|---|---|---|
| 页面访问 | ❌ 仅 `match.html`、`qa.html` 2 个页面埋点 `/api/view` | 其余 9 个页面无埋点；`page_views.page` 存 `'match'`/`'qa'` 非完整路径 |
| 来源渠道 | ❌ `page_views` 无 referrer 字段 | 无法区分微信内打开 vs 浏览器直开 |
| 注册 | ❌ `auth/verify.js` 新建用户时不写日志 | 无注册行为记录 |
| 登录 | ❌ `verify.js` / `code-login.js` 均不写日志 | 无登录行为记录 |
| 完成测试 | ⚠️ `track.js` 记录 `quiz_completed`，但 `/quiz/save`（SoulMirror 本地测评）不写 | 本地测评完成无日志 |
| 查看结果 | ❌ 无 | 需求为「查看结果」独立行为 |
| 创建提问箱 | ⚠️ 提问箱基于用户 profile 隐式存在，无「创建」动作 | 可考虑 `askbox_create` 或跳过 |
| 查看提问箱 | ❌ 无 | `askbox_view` 行为 |
| 提交问题 | ✅ `askbox_question` | — |
| 查看回答 | ❌ 无 | `askbox_view_answer` 行为 |
| 塔罗分析 | ❌ 仅写 `tarot_readings` 表，不写 activity_log | 无 `tarot_analyze` 行为 |
| 收藏 | ❌ 全站无收藏功能（前后端均无） | 功能与埋点均缺失 |
| 分享 | ❌ 前端有分享文案，无埋点 | 无 `share` 行为 |

**结论**：现有 `activity_log` 结构**不满足**完整用户活动中心需求，但表结构可复用（补充字段即可），不需要建新表。

### 3.2 提问箱数据分析

| 目标 | 现状 |
|---|---|
| 创建者是谁 | ✅ `askbox_questions.target_id` → `users` |
| 唯一 ID | ⚠️ 问题有 `id`，但提问箱本身无独立 ID（以 `target_id` 即用户 ID 为身份） |
| 访问次数 | ❌ 无任何记录 |
| 收到问题数量 | ✅ 可聚合：`COUNT(*) WHERE target_id = ?` |
| 回答数量 | ✅ 可聚合：`COUNT(*) WHERE target_id=? AND answered_at IS NOT NULL` |
| 回答率 | ➖ 可由上面两者计算，但无现成 API |
| 谁提交 | ✅ `asker_id`（匿名则为 NULL + `visitor_token`） |
| 提交时间 | ✅ `created_at` |
| 提问对象 | ✅ `target_id` |
| 属于哪个提问箱 | ⚠️ 无提问箱表，依赖 `target_id` |
| 是否回答 | ✅ `answered_at IS NOT NULL` |
| 是否公开 | ✅ `answer_visibility`（public/private） |

**结论**：askbox 数据表基本可支撑统计，但缺「提问箱访问次数」记录，且**没有后台管理 API 和页面**。

## 四、数据库设计方案

> 设计原则：**不删除数据、不破坏现有表、全部以 ALTER + CREATE 增量迁移**，与项目既有 S01~S08 迁移惯例一致。

### 4.1 升级 1：`activity_log` 补充字段（迁移 S09）

```sql
-- 行为端补充设备/来源/页面信息
ALTER TABLE activity_log ADD COLUMN device TEXT DEFAULT '';      -- mobile/desktop/tablet
ALTER TABLE activity_log ADD COLUMN os TEXT DEFAULT '';
ALTER TABLE activity_log ADD COLUMN browser TEXT DEFAULT '';
ALTER TABLE activity_log ADD COLUMN referrer TEXT DEFAULT '';      -- document.referrer
ALTER TABLE activity_log ADD COLUMN page_path TEXT DEFAULT '';     -- 如 /qa.html
ALTER TABLE activity_log ADD COLUMN detail_json TEXT DEFAULT '';   -- 扩展详情（预留，如收藏对象）
```

- 现有 6 个写入点的本地 `logActivity` 函数统一收敛到 `_lib/ip.js` 的 `logActivity`（补充 device/os/browser/referrer/page_path 参数）
- 新增 action 枚举约定：
  - `page_view`（页面访问，可选，page_views 为主)
  - `register` / `login`
  - `quiz_completed`（保留）/ `quiz_view_result`
  - `askbox_view` / `askbox_view_answer`
  - `tarot_analyze`
  - `favorite_add` / `share`
  - 保留：`wall_post` / `askbox_question` / `askbox_answer` / `askbox_reply`

### 4.2 升级 2：`page_views` 表重构（迁移 S09）

```sql
-- 补充字段（现有数据保留，新字段默认空）
ALTER TABLE page_views ADD COLUMN visitor_token TEXT DEFAULT '';
ALTER TABLE page_views ADD COLUMN referrer TEXT DEFAULT '';
ALTER TABLE page_views ADD COLUMN device TEXT DEFAULT '';
ALTER TABLE page_views ADD COLUMN os TEXT DEFAULT '';
ALTER TABLE page_views ADD COLUMN browser TEXT DEFAULT '';

CREATE INDEX IF NOT EXISTS idx_page_views_visitor ON page_views(visitor_token, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_page_views_page_created ON page_views(page, created_at DESC);
```

- `page` 字段规范化为完整路径：`/`、`/index.html`、`/qa.html`、`/tarot.html`…
- `/api/view` 升级：接收 `page / referrer / visitorToken`，后端用 UA 解析 device/os/browser，识别登录态 user_id

### 4.3 升级 3：提问箱访问统计（迁移 S09）

推荐方案 A「加表」：

```sql
CREATE TABLE IF NOT EXISTS askbox_visits (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    target_user_id INTEGER NOT NULL,      -- 提问箱主人
    visitor_id TEXT DEFAULT '',           -- 访客身份（visitor_token 或 visitor_id）
    user_id INTEGER DEFAULT NULL,         -- 登录用户
    referrer TEXT DEFAULT '',
    created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_askbox_visits_target ON askbox_visits(target_user_id, created_at DESC);
```

> 备选方案 B：用 `activity_log` 写 `action='askbox_view'`（不新增表，但查询按 target_type/target_id 过滤；缺点是 activity_log 持续膨胀）。  
> **推荐 A**：独立表避免 activity_log 膨胀，且能与问题表 JOIN 计算回答率。

### 4.4 升级 4：用户画像预留表（预留，二期）

```sql
-- 二期启用：用户兴趣标签（由行为聚合推导，或用户自选）
CREATE TABLE IF NOT EXISTS user_interest_labels (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    label TEXT NOT NULL,                  -- 如：塔罗爱好者 / 测评活跃 / 提问箱创作者
    weight INTEGER NOT NULL DEFAULT 1,    -- 权重
    updated_at INTEGER NOT NULL,
    UNIQUE(user_id, label)

```

### 4.5 不新增大表的情况说明

- 数据总览（UV/PV/注册/提问/回答/测试/塔罗）**不需要新表**，全部由现有表聚合 + 新增索引支撑：
  - `page_views`（PV/UV）
  - `users`（注册数）
  - `askbox_questions`（提问/回答数）
  - `quiz_results`（测试完成数）
  - `tarot_readings`（塔罗分析数）

## 六、前端页面设计方案

### 6.1 统一埋点 SDK（新增）

推荐新增 `track.js` 静态文件（根目录，类似 `auth.js`），所有页面 `<script src="/track.js">` 引入：

```js
// 自动上报页面访问
(function(){
  fetch('/api/view', {
    method: 'POST',
    headers: {'Content-Type':'application/json'},
    body: JSON.stringify({
      page: location.pathname,          // 全路径
      referrer: document.referrer,      // 来源
      visitorToken: getCookie('visitor_id') || getCookie('visitor_token') || ''
    })
  }).catch(()=>{});
})();

// 全局事件上报
window.trackEvent = function(action, targetType, targetId, content) {
  fetch('/api/event', {
    method: 'POST',
    headers: {'Content-Type':'application/json'},
    body: JSON.stringify({ action, targetType, targetId, content, page: location.pathname, referrer: document.referrer })
  }).catch(()=>{});
};
```

各页面业务点调用 `trackEvent`：
- 登录成功（auth.js 内部 or 页面回调）
- 查看结果（match.html、tarot.html）
- 打开提问箱（qa.html）
- 收藏/分享（预留）

### 6.2 new_admin.html 重构（9 菜单）

```

├── 近14天 PV/UV 趋势图
└── Top 页面排行
```

## 八、风险点

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 1 | **线上 D1 是否与 schema.sql 完全一致未验证**（wrangler.toml 无显式 DB 绑定名） | 高 | 迁移执行前先 `wrangler d1 list` + `wrangler d1 execute <name> --command "SELECT name FROM sqlite_master WHERE type='table'"` 核对 |
| 2 | `ALTER TABLE` 对**已有大量数据的表**（activity_log / page_views）在生产 D1 执行有锁表/耗时风险 | 中 | 迁移在低峰执行；D1 支持在线 ALTER；先备份 |
| 3 | 埋点可能导致 **activity_log / page_views 数据量快速增长**（每页面访问 +1） | 中 | page_views 单独表控制；问卷日 PV 量级小可接受；预留归档策略 |
| 4 | 统一 logActivity 重构回归（6 处调用方） | 中 | 参数兼容旧调用（新增字段默认值）；逐一测试 |
| 5 | `visitor_id` 与 `visitor_token` 双标识并存增理解复杂度 | 低 | 文档明确：`visitor_id`=浏览器持久身份(S-07)，`visitor_token`=匿名提问临时身份，两者都写入 page_views |
| 6 | 前端 11 页面逐个加埋点工作量与遗漏风险 | 中 | 用共享 `track.js` 自动上报，页面仅需引一行 script |
| 7 | 提问箱访问计数在 GET 接口内联写入可能被刷 | 低 | askbox_visits 仅记录，不设上限；后台展示端去重 UV |
| 8 | 后台 9 菜单重构影响现有操作员使用 | 中 | 保留现有 Tab 名称与数据，增量新增；灰度上线 |
| 9 | 旧 `admin.html` 备份（admin-legacy.html）与 new_admin.html 并存，改错文件 | 低 | 明确改造目标是 `new_admin.html`；admin.html 保持跳转壳不动 |
