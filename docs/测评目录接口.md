## 1. 设计目标

1. **数量不写死**：轮盘卡片数量完全由 `quizzes` 表里 `status = 'published'` 的记录数决定。
2. **没有数据就空着**：一条已发布测评都没有时，页面显示空状态，不出现假卡片。
3. **新增测试不改前端**：通过管理接口写入一条记录并发布，轮盘自动多一张卡。
4. **任意数量都能循环**：1 条、5 条、30 条都按同一套弧线循环；数量多时只渲染中心附近几张。
5. **题目与展示分离**：目录接口只返回卡片信息，不返回题目；单条接口才带 `questions`。

## 2. 数据流

```
管理员 / 脚本
   │ POST /api/admin/quizzes（需 is_admin 会话）
   ▼
D1: quizzes
   │ GET /api/quizzes（只返回 published）
   ▼
assess.html
   loadCatalog() → normalizeQuiz() → build() → 轮盘
   │ 点击卡片 → 翻转详情 → entryUrl（/match.html、/sm-test.html…）
   ▼
GET /api/quiz-history（登录后）→ 历史测评抽屉
```

`prototype/assess-wheel.html` 保留为视觉原型；正式页面是 `assess.html`，两者共用同一套数据字段与轮盘逻辑。

## 3. 表结构

迁移文件：`docs/migrations/2026-11-04-S14-quiz-catalog.sql`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | 自增主键 |
| `slug` | TEXT UNIQUE | 稳定标识，小写字母/数字/连字符，2–64 位；发布后不建议改 |
| `title` | TEXT | 卡片大标题，必填，≤80 字 |
| `category` | TEXT | 分类，如「亲密关系」「人格」「成长」 |
| `subtitle` | TEXT | 卡片副题，一句短句 |
| `description` | TEXT | 详情页导语，≤500 字 |
| `question_count` | INTEGER | 题数（展示用） |
| `duration_minutes` | INTEGER | 预计分钟数（展示用） |
| `participant_count` | INTEGER | 参与人数（展示用，当前为人工填写） |
| `points_json` | TEXT | 字符串数组，详情页「会帮你看清」3–8 条 |
| `questions_json` | TEXT | 题目数组，答题器解释；服务端只校验数组与大小 |
| `entry_url` | TEXT | 点击「开始测试」后的站内跳转地址，如 `/match.html`、`/sm-test.html`；必须以 `/` 开头，不允许站外地址 |
| `icon` | TEXT | 图标名，见 §6 |
| `tint` | TEXT | 可选 CSS 颜色；为空时前端按索引取默认色 |
| `badge` | TEXT | 可选角标文字，如「主推」「热门」 |
| `badge_class` | TEXT | 目前只支持 `deep`（深色角标） |
| `status` | TEXT | `draft` / `published` / `archived`，默认 `draft` |
| `sort_order` | INTEGER | 越小越靠前，默认 0 |
| `created_at` | INTEGER | 毫秒时间戳 |
| `updated_at` | INTEGER | 毫秒时间戳 |

索引：`idx_quizzes_status_sort (status, sort_order, id)`。

### questions 的建议结构

服务端不强制题目内部结构，方便以后换题型。当前建议：

```json
[
  {
    "id": "q1",
    "text": "当关系变得亲密时，你通常会……",
    "options": [
      { "text": "很自然地靠近", "scores": { "secure": 2 } },
      { "text": "想先退一步", "scores": { "avoidant": 2 } }
    ]
  }
]
```

以后做通用答题器时，可以在这里追加 `mode`、`reverse`、`dimensions` 等字段，不需要改表。

## 4. 公开接口

### GET /api/quizzes

返回全部已发布测评（不含题目）。

```bash
curl https://soulmirror-255.pages.dev/api/quizzes
```

```json
{
  "items": [
    {
      "id": 1,
      "slug": "attachment",
      "title": "依恋类型",
      "category": "亲密关系",
      "subtitle": "你在亲密关系里，习惯怎样靠近",
      "description": "8 道情境题，帮你看清自己在关系中的安全感来源。",
      "questionCount": 8,
      "durationMinutes": 3,
      "participantCount": 0,
      "points": ["你在关系里的默认靠近方式", "哪些时刻你最容易后退", "什么样的回应会让你感到安全"],
      "entryUrl": "/match.html",
      "icon": "heart",
      "tint": "",
      "badge": "热门",
      "badgeClass": "",
      "sortOrder": 10,
      "createdAt": 1760000000000,
      "updatedAt": 1760000000000
    }
  ],
  "total": 1
}
```

- 只返回 `status = 'published'`。
- 按 `sort_order ASC, id ASC` 排序。
- 没有记录时返回 `{ "items": [], "total": 0 }`，前端显示空状态。
- 限流：每 IP 120 次/分钟。
- 缓存：`Cache-Control: public, max-age=30, must-revalidate`。

### GET /api/quizzes?slug=attachment

返回单条已发布测评，**含 `questions`**。

```bash
curl "https://soulmirror-255.pages.dev/api/quizzes?slug=attachment"
```

未发布或不存在返回 404 `{ "error": "not_found" }`。

## 5. 管理接口

路径：`/api/admin/quizzes`
权限：必须携带管理员 `session` Cookie（`users.is_admin = 1`），否则 403。

| 方法 | 用途 |
|------|------|
| GET | 列表（含草稿/归档）或单条详情（含题目） |
| POST | 新建单条，或 `items` 批量新建；`upsert: true` 按 slug 覆盖 |
| PUT `?id=` | 全量更新一条 |
| DELETE `?id=` | 软删除：`status = 'archived'` |

### 查询

```bash
# 全部（含草稿/归档，最多 500 条）
curl -b cookies.txt "https://soulmirror-255.pages.dev/api/admin/quizzes"

# 只看已发布
curl -b cookies.txt "https://soulmirror-255.pages.dev/api/admin/quizzes?status=published"

# 单条详情（含题目）
curl -b cookies.txt "https://soulmirror-255.pages.dev/api/admin/quizzes?id=1"
curl -b cookies.txt "https://soulmirror-255.pages.dev/api/admin/quizzes?slug=attachment"
```

### 新建一条（先存草稿）

```bash
curl -X POST "https://soulmirror-255.pages.dev/api/admin/quizzes" \
  -b cookies.txt \
  -H "Content-Type: application/json" \
  -d '{
    "slug": "attachment",
    "title": "依恋类型",
    "category": "亲密关系",
    "subtitle": "你在亲密关系里，习惯怎样靠近",
    "description": "8 道情境题，帮你看清自己在关系中的安全感来源、靠近方式，以及容易卡住的地方。",
    "questionCount": 8,
    "durationMinutes": 3,
    "participantCount": 0,
    "points": [
      "你在关系里的默认靠近方式",
      "哪些时刻你最容易后退",
      "什么样的回应会让你感到安全"
    ],
    "questions": [
      {
        "id": "q1",
        "text": "当关系变得亲密时，你通常会……",
        "options": [
          { "text": "很自然地靠近", "scores": { "secure": 2 } },
          { "text": "想先退一步", "scores": { "avoidant": 2 } }
        ]
      }
    ],
    "entryUrl": "/match.html",
    "icon": "heart",
    "badge": "热门",
    "status": "draft",
    "sortOrder": 10
  }'
```

成功返回 201，`item.id` 为新记录 ID。

### 发布 / 更新

`PUT` 是全量更新，**未传的字段会被重置为默认值**，所以要把当前值一起传回。

```bash
curl -X PUT "https://soulmirror-255.pages.dev/api/admin/quizzes?id=1" \
  -b cookies.txt \
  -H "Content-Type: application/json" \
  -d '{ "slug": "attachment", "title": "依恋类型", "status": "published", "sortOrder": 10, "...": "其余字段同上" }'
```

也可以直接 `POST` 一条 `status: "published"` 的记录。

### 批量导入

```json
{
  "upsert": true,
  "items": [
    { "slug": "attachment", "title": "依恋类型", "status": "published" },
    { "slug": "love-language", "title": "五种爱之语", "status": "published" }
  ]
}
```

- 单次最多 100 条。
- 逐条校验；部分失败返回 207，`created` 与 `errors` 分别列出结果。
- `upsert: true` 时按 `slug` 覆盖，适合从题库批量同步。

### 归档

```bash
curl -X DELETE "https://soulmirror-255.pages.dev/api/admin/quizzes?id=1" -b cookies.txt
```

归档后公开接口不再返回，但记录和题目仍保留，可随时改回 `published`。

### 校验规则

- `slug`：`^[a-z0-9][a-z0-9-]{1,63}$`
- `title`：必填，≤80
- `status`：只能是 `draft` / `published` / `archived`
- `points`：最多 8 条，每条 ≤120 字
- `questions`：最多 300 条，序列化后 ≤200KB
- `entryUrl`：可空；非空时必须以 `/` 开头、不能是 `//`，不能含空白、引号、尖括号、反斜杠
- `badgeClass`：前端只认 `deep`，其他值会被忽略样式

## 6. 前端字段映射与图标

`prototype/assess-wheel.html` 的 `normalizeQuiz()` 把接口字段转成卡片字段：

| 接口字段 | 卡片字段 | 说明 |
|----------|----------|------|
| `title` | `title` | 大标题 |
| `category` | `cat` | 顶部栏目名 |
| `subtitle` | `sub` | 副题 |
| `description` | `desc` | 导语，最多两行 |
| `questionCount` / `durationMinutes` / `participantCount` | `meta` | 自动拼成 `8 题 · 3 分钟 · 731 人测过`；人数为 0 时省略 |
| `points` | `points` | 详情页 bullet；不足 3 条时用默认文案补齐 |
| `icon` | `icon` | 见下方图标名 |
| `tint` | `tint` | 可选，CSS 颜色 |
| `badge` / `badgeClass` | `badge` / `badgeClass` | 角标 |
| `entryUrl` | `entryUrl` | 点击「开始测试」后的站内跳转地址；为空时不跳转 |

可用图标名：
`compass`、`circles`、`heart`、`pentagon`、`compass2`、`split`、`star`、`bolt`、`wave`、`shield`、`book`、`users`。
未知图标会回退到 `compass`。

## 7. 新增一个测试的完整流程

1. 准备一个 JSON（参考 §5 新建示例），`status` 先写 `draft`。
2. 用管理员账号登录站点，拿到 `session` Cookie。
3. `POST /api/admin/quizzes` 写入。
4. `GET /api/admin/quizzes?slug=xxx` 检查字段与题目。
5. 把 `status` 改成 `published`（`PUT` 全量更新，或 `POST + upsert`）。
6. 打开 `/api/quizzes` 确认它出现在列表里。
7. 打开测评中心，卡片应自动多一张；无需改 HTML/JS。

## 8. 轮盘如何适应任意数量

- `N = items.length`。
- 手机：`N <= 5` 时全部显示；`N > 5` 时只渲染中心附近 5 张。
- 桌面：`N <= 7` 时全部显示；`N > 7` 时只渲染中心附近 5 张。
- 拖动 / 滚轮 / 方向键都按 `N` 取模循环，不会因为数量变化越界。
- 圆点：`N <= 14` 时显示；更多时隐藏，避免底部挤满。
- 空目录：隐藏轮盘与页码，显示「还没有测评」。

## 9.5 历史记录接口

`GET /api/quiz-history`

- 必须登录；未登录返回 401。
- 合并两类记录，按时间倒序，最多 20 条：
  - `quiz_results`：深度匹配测评，`type = "deep"`，跳转 `/match.html`。
  - `sm_test_results`：S/M 互动倾向，`type = "sm"`，跳转 `/sm-test.html`。
- 返回 `items[]`，每条包含 `id`、`type`、`title`、`createdAt`、`summary`。
- 响应头 `Cache-Control: no-store`。
- 页面入口：`assess.html` 右上角「测评记录」，或 `assess.html?history=1` 自动打开。
- 用户菜单也增加了「我的测评记录」，指向 `assess.html?history=1`。
