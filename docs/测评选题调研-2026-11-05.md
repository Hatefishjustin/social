# 心镜 SoulMirror 测评选题调研（2026-11-05）

> 调研目的：为测评中心补充「高转发、好玩、能吸流」的新测试，并给出可直接落地的选题与字段映射方案。
>
> 结论先行：**优先做「恋爱脑浓度」「精神状态图鉴（去病理化改版）」「宿舍生存人格」三个方向**。其中「精神状态图鉴」转发潜力最高，但必须重写标签与文案；「宿舍生存人格」最适合作为第一步冷启动试点，因为它天然长在校园群里，合规风险也最低。

## 0. 先说三条判断

1. **现在最能转的不是“更科学的测评”，而是“更像社交货币的测试”**：结果要能截图、能当自我介绍、能 @ 一个具体的人。MBTI 之后，SBTI 在 2026 年 4 月用“抽象标签 + 自嘲”把这条路又走了一遍，甚至把测试页面挤崩。
2. **关系型测试的转发效率高于个人型测试**。个人测试是“我是什么”，关系测试是“我们是什么”；后者自带一个必须被 @ 的人。CPTI 把这一点做得很直白：不是测你俩各自是谁，而是给你俩的关系命名。
3. **合规不是事后补丁，而是选题的一部分**。面向中学生/大学生，最容易踩的三条线是：临床/病名化标签、负面向下的自我暗示、以及微信外链对“H5 测试类内容”的限制。选题阶段就要决定“哪些词不能用”。

## 1. 调研方法与证据边界

- 检索时间：2026-11-05。
- 检索范围：微博、小红书、抖音、B 站、微信公众号公开报道/话题页，以及千瓜、易观、后浪研究所等第三方数据报道的二手引用。
- 证据分级：
  - A 级：官方媒体/平台官方规则/可复核的产品页。
  - B 级：行业媒体、数据机构报道、公开产品页。
  - C 级：单一自媒体观察，仅用于佐证趋势，不单独作为结论依据。
- 数据口径提醒：同一话题在不同平台、不同统计时点的数字差异很大（例如 MBTI 在微博/抖音/小红书的公开数字从“十几亿”到“几十亿”都有）。本文的数字只用于判断**量级**，不作为精确结论。
- QQ 空间/微信群没有公开可查的统一热度口径，主要作为二次传播渠道存在；本次不对其做量化，只做机制判断。

### 2.2 这些案例的共同结构

不是“心理学量表 + 报告”，而是：

```
一个具体场景 → 一个可命名标签 → 一张可截图结果 → 一个可 @ 的人 → 一句可复述的梗
```

MBTI 给的是“身份标签”，SBTI 给的是“自嘲标签”，CPTI 给的是“关系命名”，网易云给的是“视觉标签”，恋爱脑给的是“浓度标签”。形式不同，结构一样。

## 3. 为什么这类测试会被转发

1. **结果可截图，且截图成本低。** 大字标题 + 一个标签 + 一句扎心/好笑的文案，用户不需要解释就能发。网易云主导色、SBTI 结果页都是这个逻辑。
2. **标签有身份感。** “我是 INFP”“我是淡人”“我是吗喽”可以写进自我介绍、群昵称、朋友圈签名。标签越短，越容易被复用。
3. **低成本互动。** 个人测试的转发是“你看我”，关系测试的转发是“你看我们”。后者自带一个必须被 @ 的人：对象、闺蜜、室友、搭子。CPTI/情侣默契/宿舍测试都吃到了这一点。
4. **结论可争议。** “准”会让人惊讶，“不准”会让人想反驳；两种反应都能产生评论和二次传播。SBTI 的“冒犯感”就是争议燃料，但这也是它最大的合规风险。
5. **有梗、有自嘲。** 吗喽、水豚、浓人淡人、SBTI 都不是“夸你”，而是“替你把说不出口的疲惫说出来”。自嘲降低了分享的心理门槛：不是我在炫耀，是我们在玩。
6. **有时效/FOMO。** 热搜、服务器崩溃、“今天你测了吗”会制造“再不测就落伍”的感觉。SBTI 在 2026 年 4 月就是典型的短时间集中爆发。
7. **关系命名比类型学更“可聊”。** “我们是互补型/拉扯型/搭子型”比“我是 ENFP”更容易开启对话，因为它需要一个共同语境。

## 4. 候选测试评分与排序

评分口径：

- **转发潜力 P（1–5）**：基于公开案例的量级、分享机制强度、是否自带“被 @ 的人”。
- **制作成本 C（1–5，越低越好）**：1 = 纯前端静态 + 一条 D1 目录；5 = 需要 AI 接口、内容安全、限流、降级。
- **合规风险 R（1–5，越低越好）**：1 = 低；3 = 中，需要改写/免责声明；5 = 高，不建议原样上线。
- **综合分 = P×0.55 + (6−C)×0.25 + (6−R)×0.20**。
- **风险是一票否决项**：R≥4 的选题，必须先改到 R≤3 才能上线；分数只用于排序，不替代合规判断。

## 5. 候选测试详情

### 5.1 恋爱脑浓度检测（slug: `lovebrain-level`）

**标题**：恋爱脑浓度检测：你是清醒人机，还是恋爱脑王者？

**一句话卖点**：不是骂你恋爱脑，是帮你算出你还有多少理智在线。

**题目设计**：
- 12 道题，约 3 分钟；10 道情境单选 + 2 道两难选择（“对象和异性吃饭，你更受不了哪一种”）。
- 每题 4 个选项，按 0–3 分计；总分映射到 6 个浓度档。
- 测什么：投入速度、边界感、自我安抚、理想化程度、患得患失、行动冲动。不是临床量表，但题目要自洽：越靠近“必须立刻确认/放弃自己的安排/反复查看手机”，分数越高。
- 题目示例：“对方三小时没回消息，你更接近哪种状态？”选项从“忙自己的，等 TA 方便”到“已经开始编辑第三条消息”。

**结果设计**：
- 6 档结果：`清醒人机`（0–20）、`微上头`（21–40）、`心动预备役`（41–60）、`标准恋爱脑`（61–75）、`重灾区`（76–90）、`恋爱脑王者`（91–100）。
- 结果页元素：大号浓度数字 + 浓度条 + 结果标签 + 一句“症状总结” + 3 条典型表现 + 2 条“急救建议” + “你的嘴硬指数”。
- 分享文案模板：“我的恋爱脑浓度 87%：嘴上说无所谓，身体很诚实。@XXX 你敢测吗？”
- 分享卡：深色底 + 大数字 + 标签 + 一句扎心文案 + 站点二维码。

**传播机制**：
- 分享卡；好友互猜（“猜猜我的浓度”）；情侣/暧昧对象对比（同一链接，两人分别作答后看差值）；朋友互骂式转发。
- 不做公开排行榜，避免羞辱和霸凌；只做私密对比。

**落地成本**：
- 纯前端静态可做；需要 D1 目录一条记录；需要 `/quiz.html` 通用答题器。
- 计分不是现有 `type`/`scale` 模式，需要给答题器加一个 `score` 模式（或按 6 个维度加权后取最高档，但不如直接分数自然）。

**字段映射**：
- `slug`、`title`、`category`、`subtitle`、`description`、`question_count`、`duration_minutes`、`points_json`、`entry_url`、`icon`、`tint`、`badge`、`badge_class`、`status`、`sort_order` 都可直接写。
- 缺口：`quizzes` 没有 `results_json`/`mode` 字段，结果档位和计分规则只能放在静态 `quiz-data.js` 或新增字段；`questions_json` 的格式与 `quiz-data.js` 不一致，不能直接把静态题库原样塞进 D1。

**合规注意**：
- 不用“病/症/患者/没救/恋爱脑晚期”等病名化表达；标题可以用“恋爱脑”，但正文要说明“这是玩笑式的上头指数，不是心理诊断”。
- 不奖励查手机、跟踪、控制、孤立对方等行为；题目里不能把“占有欲”包装成“深情”。
- 未成年人场景去性化：不写同居、性行为、怀孕、堕胎等情境。
- 结果页加一句健康关系提示：“好的关系不会让你一直处在待机状态。”

**依据**：抖音“恋爱脑”相关播放量 231.9 亿、微博 #恋爱脑# 1.9 亿、小红书“骂醒恋爱脑”2000 万+（[大众网](http://www.dzwww.com/xinwen/shehuixinwen/202307/t20230721_12413416.htm)、[红网](https://moment.rednet.cn/content/646948/69/14906962.html)）。

### 5.2 精神状态图鉴（去病理化改版，slug: `mind-state`）

**标题**：精神状态图鉴：你是哪种抽象人类？

**一句话卖点**：不诊断、不贴病名，只负责把你今天的精神状态说得很好笑。

**题目设计**：
- 18 道单选 + 2 道两难，约 4 分钟；全部四选一，适合手机。
- 场景覆盖：早八、群消息、考试周、DDL、食堂、室友、家庭群、朋友圈、深夜刷手机、网购、追星/嗑 CP、游戏、通勤、放假、开学、毕业、AI、社交回血。
- 测什么：能量水平、社交电量、拖延方式、情绪表达、网络人格、日常应对策略。结果不追求“准”，追求“说到心坎里”。
- 不碰：自伤、抑郁、焦虑症、ADHD、双相、创伤、原生家庭伤害等临床/创伤主题。

**结果设计**：
- 16 个结果标签，命名要“好笑但不伤人”：
  - `早八猴`、`水豚型`（稳定发疯）、`省电模式`、`NPC 型`（背景板人格）、`人间充电宝`、`夜行生物`、`嘴替型`、`已读不回猫`、`社交回血包`、`精神股东`、`拖延艺术家`、`计划型选手`、`情绪天气预报`、`反内耗专员`、`小圈子守门员`、`热闹旁观者`。
- 结果页元素：大标签 + 3 个“今日症状” + 一条能量条（如“稳定 70% / 想消失 30%”）+ 一句建议 + “你的搭子类型”。
- 分享文案模板：“今日精神状态：早八猴。不是不想努力，是电量只够撑到第二节课。”
- 分享卡：大字标签 + 3 个关键词 + 一句文案 + 二维码。

**传播机制**：
- 分享卡；“今天你是什么”@好友；“精神状态图鉴”收集（不排名）；可做“今日版/本周版”制造重复参与。
- 不做“确诊”“患者”话术；不做公开类型排行榜。

**落地成本**：

- 分享文案模板：“2027 年的我给我写了一封信：先别急着证明自己，你已经在路上了。”
- 分享卡：信件摘录 + 未来身份 + 二维码。

**传播机制**：
- 分享信；“让 AI 也给你写一封”；朋友对比“AI 觉得你未来会干嘛”。
- 不做“算命/预测”话术；不做“考试必过/发财/恋爱成功”的承诺。

**落地成本**：
- 需要 AI 接口（可复用现有 DashScope `qwen-plus` 封装）；需要 D1 目录一条记录；需要内容安全、限流、降级文案、结果缓存/不缓存策略。
- 成本本组最高；建议等通用答题器和分享卡跑通后再做。

**字段映射**：
- 目录字段全部可写；`entry_url` 指向 `/quiz.html?slug=ai-future-letter` 或独立的 AI 结果页。
- **不可行/缺口**：`quizzes` 没有 AI 配置字段（prompt/模型/温度/敏感词策略）；没有通用结果表；AI 生成内容没有审核字段。需要新增 `ai_config_json` 或独立配置，以及结果审核/降级机制。

**合规注意**：
- 不叫“算命/预测/占卜”；不承诺考试、健康、财富、感情结果；AI 生成内容标注“AI 生成，仅供娱乐”。
- 不采集敏感个人信息；不做“上传照片看未来”；不做“AI 看手相/看面相”。
- 需要内容安全过滤和人工抽检；未成年人模式下避免职业/收入暗示。

**依据**：AI 算命在小红书 #deepseek算命 5608 万浏览、#玄学 42 亿；18–30 岁 60% 体验过 AI 算命（[36 氪](https://eu.36kr.com/zh/p/3885616737054721)、[澎湃新闻](https://m.thepaper.cn/newsDetail_forward_33079198)、[搜狐转载报告](https://m.sohu.com/a/921109568_122205396/)）；但本候选刻意避开“算命”，只做“未来信件”。

## 6. 与现有 `quizzes` 表的字段映射

字段以 [docs/migrations/2026-11-04-S14-quiz-catalog.sql](2026-11-04-S14-quiz-catalog.sql) 与 [docs/测评目录接口.md](测评目录接口.md) 为准。

| 字段 | 候选能否直接用 | 说明 |
|---|---|---|
| `slug` | 可以 | 用 `lovebrain-level`、`mind-state`、`dorm-persona`、`social-animal`、`persona-ingredients`、`mood-color`、`relation-duo`、`ai-future-letter`；需符合 `^[a-z0-9][a-z0-9-]{1,63}$` |
| `title` | 可以 | ≤80 字；上面的标题都在范围内 |
| `category` | 可以 | 建议：`关系`/`人格`/`校园`/`情绪`/`趣味`；表是 TEXT，不强制枚举 |
| `subtitle` | 可以 | 一句话副题 |
| `description` | 可以 | ≤500 字；写“玩什么、怎么玩、不适合谁” |
| `question_count` | 可以 | 展示用，需与题库实际题数一致 |
| `duration_minutes` | 可以 | 展示用 |
| `participant_count` | 可以，但只能人工填 | 当前没有按 `slug` 聚合的通用结果表，无法自动累计 |
| `points_json` | 可以 | 3–8 条，每条 ≤120 字 |
| `questions_json` | **部分可行** | 服务端只校验“数组 + ≤300 条 + ≤200KB”，但现有 `quiz-data.js` 的题目格式是 `options[].t/v`、`scale` 用 `dim/reverse`；接口文档示例是 `options[].text/scores`。直接搬运会格式不一致；需要统一 canonical 格式，或继续用静态题库 |
| `entry_url` | 可以 | 用 `/quiz.html?slug=xxx`；必须显式填写。注意：schema 注释说“空则回退 /quiz.html?slug=”，但 `assess.html` 的 `startOpenedTest()` 实际只在 `entryUrl` 非空时跳转，空值不会自动回退 |
| `icon` | 可以 | 只能用接口文档列出的 `compass/circles/heart/pentagon/compass2/split/star/bolt/wave/shield/book/users`；`spark` 是表默认值但不在文档列表，未知会回退 `compass` |
| `tint` | 可以 | CSS 颜色；为空时前端按索引取默认色 |
| `badge` / `badge_class` | 可以 | `badge_class` 目前只认 `deep` |
| `status` / `sort_order` | 可以 | `draft`/`published`/`archived`；排序 asc |

### 6.1 明确的缺口（不新增字段就做不了）

1. **没有 `results_json` / `results` 字段**：结果数量、结果名、结果文案、分享文案模板都无处存放。当前 `quiz-data.js` 把结果文案写在 `dimensions` 里，但那是静态文件；D1 只有目录和题目。要做“D1 单一数据源”，必须加字段。
2. **没有 `mode` 字段**：现有 `quiz-data.js` 有 `type`/`scale` 两种模式；恋爱脑需要 `score`，成分表需要百分比，双人需要 `duo`。`questions_json` 里可以塞 `mode`，但服务端不校验，前端也不一定读。
3. **没有通用结果表**：`quiz_results` 是 41 题深度测评专用（字段是 `headline/scores_json/answers_json`，没有 `quiz_slug`）；`sm_test_results` 是 S/M 专用；`quiz-history` 只合并这两类。通用测试目前**无法保存结果、无法反查、无法自动统计人数**。
4. **没有 `min_age` / `age_gate` 字段**：S/M 的 18+ 只在页面文案；如果要做年龄门，需要服务端字段/校验，而不是只靠前端。
5. **没有分享配置字段**：分享卡背景、标题、二维码位置、分享文案模板目前只能写死在前端。
6. **没有 AI 配置字段**：prompt、模型、温度、敏感词、降级文案都无处放。

### 6.2 现有代码里另外三个需要先处理的坑

1. **`/quiz.html` 不存在**：`quiz-data.js` 已经有 10 个题库（attachment、love-language、big-five、values、conflict、campus-role、social-energy、emotion、boundaries、study-drive），但没有任何页面渲染它们；`QUIZ_INDEX` 里的 `href` 指向 `/quiz.html?id=...`，也是空链接。
2. **`friendship` 只有索引、没有题库**：`QUIZ_INDEX` 第 12 条是 `friendship`（友情模式），但 `QUIZ_BANK` 里没有对应定义。直接上线 `/quiz.html?slug=friendship` 会拿不到题。要么补题库，要么先移除索引。
3. **参数名不统一**：`quiz-data.js` 的 `QUIZ_INDEX` 用 `?id=`，S14 文档和 D1 用 `?slug=`。建议统一为 `?slug=`，并让 `/quiz.html` 同时兼容 `id` 作为旧别名（只做兼容，不作为新标准）。

## 7. 落地路线：第一步不是写 8 条目录，而是先做通用答题器

### 7.1 第一步（建议本周做）

1. **选一个试点：`dorm-persona`（宿舍生存人格）**。
   - 理由：校园群传播最自然；10 题 + 8 角色，制作成本最低；合规风险最低；不需要 AI。
   - 如果更看重“最快看到转发”，可以把试点换成 `lovebrain-level`；但不建议第一个就做“精神状态图鉴”，它的文案审核成本最高。
2. **做 `/quiz.html?slug=` 的最小闭环**：
   - 读取静态 `quiz-data.js` 的题库（先不依赖 D1 的 `questions_json`，避免格式双源）。
   - 渲染题目 → 计分 → 结果页 → canvas 分享卡（可复用 `match.html` 的 `generateShareImage`/`showShareModal` 思路，不引入第三方截图库）。
   - 支持 `?slug=`；`?id=` 只做兼容。
3. **D1 只写一条 `draft` 目录**：
   - `slug=dorm-persona`
   - `title=宿舍生存人格：你在寝室里是哪种角色？`
   - `category=校园`
   - `subtitle=10 个寝室名场面，测出你的宿舍生态位`
   - `description=...`（≤500 字）
   - `question_count=10`
   - `duration_minutes=3`
   - `points_json` 写 3 条
   - `entry_url=/quiz.html?slug=dorm-persona`
   - `icon=users` 或 `circles`
   - `tint` 用暖色
   - `badge=NEW`
   - `status=draft`，`sort_order=30`
4. **上线前自测**：
   - 从 `assess.html` 轮盘点卡片 → 翻转详情 → 开始测试 → 答完 10 题 → 结果页 → 保存分享图。
   - 手机尺寸下检查结果页、分享卡、二维码。
   - 埋点：`quiz_start`、`quiz_complete`、`share_click`（复用现有 `trackEvent`）。
5. **合规最小集**：
   - 结果页固定免责声明：“娱乐与自我探索性质，不构成心理诊断。”
   - 不强制登录；不收集姓名/学校/宿舍号。
   - 不做“分享后解锁结果”；分享是可选项。
6. **观察 3–7 天**：看完成率、分享点击率、群聊回访；再决定第二个做 `lovebrain-level` 还是 `mind-state`。

### 7.2 为什么不先批量写 8 条 D1 目录

- 通用答题器不存在，目录加了也点不进去。
- `entry_url` 为空不会自动回退到 `/quiz.html`（页面实际不跳）。
- `questions_json` 与 `quiz-data.js` 格式不一致，直接写 D1 会造成“目录一套、题库一套”的双源。
- 结果文案/计分模式没有字段；先写 D1 只能得到卡片，出不了结果。

### 7.3 第二阶段（验证后再做）

1. 给 `quizzes` 加 `results_json`、`mode`、`min_age`（迁移），把静态结果文案迁到 D1；或维持静态题库，只把目录放 D1。
2. 加通用结果表 `quiz_attempts`（`quiz_slug`、`user_id`、`visitor_token`、`result_key`、`scores_json`、`created_at`），接历史记录和 `participant_count` 聚合。
3. 双人关系加 `quiz_sessions`（邀请码、双方答案、过期时间）；AI 未来通知书加独立接口与内容安全。
4. 把现有 10 个题库批量上架：它们已经是写好的内容，接上 `/quiz.html` 后可以零新内容成本补齐目录。

## 8. 合规与风险清单

### 8.1 面向未成年人（本项目核心用户包含中学生）

- 不采集不满 14 周岁未成年人的个人信息；如确需收集，必须取得监护人同意。依据《网络数据安全管理条例》与《个人信息保护法》相关要求（[国务院条例](https://www.gov.cn/zhengce/zhengceku/202409/content_6977767.htm)、[网信办征求意见稿](https://www.cac.gov.cn/2026-01/10/c_1769603446094128.htm)）。
- 测试默认匿名、本地计分、不强制登录；不收集姓名、学校、班级、宿舍号、手机号、精确位置。
- 结果页用显著位置提示“娱乐与自我探索，不构成心理诊断”；如用户表达持续低落/自伤倾向，给出学校心理老师/专业机构求助信息，而不是只给一个标签。
- 《可能影响未成年人身心健康的网络信息分类办法》自 2026-03-01 起施行，对可能引发极端情绪、诱导不良行为的信息有显著提示要求（[国务院文件](https://www.gov.cn/zhengce/zhengceku/202601/content_7055963.htm)）。测试文案不要鼓励“摆烂/消失/发疯”等行为。

### 8.2 心理暗示与标签边界

- 不用临床词：抑郁症、焦虑症、ADHD、双相、人格障碍、创伤、自伤、自杀。
- 不用“确诊/患者/有病/没救”话术；用“状态/倾向/此刻/角色”。
- 不用“废物/伪人/酒鬼/送钱者/小丑/舔狗/渣男/绿茶/PUA/心机/寄生虫”等贬义标签。
- 结果页写“标签会变，人也会变”；不做“你就是这样的人”的固定化断言。
- 专家提醒：网红测试的信度/效度通常不足，反复测可能结果不同；把娱乐测试当真可能窄化自我认知（[央视网科普](https://news.cctv.com/2026/04/13/ARTImczL1ZLcH66rnRWDGP9O260413.shtml)、[江西新闻网专家访谈](https://tt.jxnews.com.cn/news/2856693)）。

### 8.3 MBTI/星座式标签的边界

- 可以借用“类型/标签”的传播形式，但不要声称“科学心理测评”；文案用“趣味/自我探索/娱乐”。
- 不用测试结果做匹配排序、性格优劣判断、职业/学业建议；不做“XX 型不适合学理科”这类断言。
- 不做星座/八字式的确定性预测；AI 未来通知书也要避免“考试必过/发财/生病”等承诺。

### 8.4 微信外链与分享机制

- 微信《外部链接内容管理规范》明确把“H5 游戏、测试类内容（性格测试、好友问答、测试签等）”列为限制对象；违规可能被停止在朋友圈传播、停止域名/IP 访问（[微信官方规范](http://weixin.qq.com/cgi-bin/readtemplate?t=weixin_external_links_content_management_specification&from=timeline&isappinstalled=0)、[解读](http://m.ikanchai.com/pcarticle/73760)）。
- 网易云「人格主导色」就是先例：刷屏当天被微信以“互动测试内容”停止访问（[红网](http://m.toutiao.com/group/6966804998113985060/)）。
- 因此：不要把微信作为唯一渠道；准备二维码、复制链接、站内分享；**不要做“分享后解锁结果/分享得次数”**，这既容易被判定为诱导分享，也会伤害体验。

### 8.5 哪些选题要避开或改表述

| 选题 | 处理 |
|---|---|
| 直接复刻 SBTI 原版 | **不建议**。负标签 + “确诊” + 未成年人 = 高风险；改造成“精神状态图鉴”，去病名化、去负标签 |
| “恋爱脑”原词 + “没救/晚期/患者” | 可保留“恋爱脑”作为玩梗标题，但正文改“上头指数”；去掉病名化、去掉“骂醒”式羞辱 |
| 宿舍“心机/双面派/最讨厌室友” | 改成中性角色（边界派/观察者/隐身人）；不做排名、不点名 |
| 情侣“渣男/绿茶/舔狗/PUA 测试” | **避开**。改为关系类型命名，不做道德审判 |
| 星座/八字“你今年必发财/必分手” | **避开确定性预测**；如做玄学，只做“娱乐式描述”，不做承诺 |
| S/M 类内容 | 维持 18+；不要放进面向未成年人的默认推荐位；服务端年龄门仍需补 |
| AI 算命/看手相/看面相 | **避开**；改做“未来通知书/夸夸信”，不采集照片、不预测命运 |
| “分享后解锁结果” | **避开**；改为可选分享 |
