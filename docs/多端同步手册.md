## 2. Windows 端

### 开始工作前

```powershell
cd D:\Github\social
git pull --rebase --autostash origin main
git status
```

### 改完后

```powershell
cd D:\Github\social
git add -A
git commit -m "type: 说明"
git push origin main
```

### 校验是否同步

```powershell
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
```

两个哈希相同即同步。

## 4. 三端一致性检查（一条命令看全）

Windows PowerShell：

```powershell
cd D:\Github\social
$local = git rev-parse HEAD
$remote = (git ls-remote origin refs/heads/main).Split("`t")[0]
$nas = (ssh -i C:/Users/Administrator/.ssh/id_ed25519_nas Justin@100.73.240.73 "cd ~/.opencode/projects/soulmirror/repo && git rev-parse HEAD").Trim()
"Windows : $local"
"GitHub  : $remote"
"NAS     : $nas"
if ($local -eq $remote -and $remote -eq $nas) { "OK 三端一致" } else { "不一致，需要同步" }
```

## 5. 常见情况

| 情况 | 处理 |
|---|---|
| 一端有未提交改动 | 先在该端 `commit`，再 `pull --rebase`，再 `push` |
| `pull` 报冲突 | 不要强推。先 `git status` 看冲突文件，手工合并后 `git add` + `git rebase --continue` |
| 两端同时改了同一文件 | 以业务正确为准手工合并；合并前先 `git fetch` 看差异 |
| NAS 断电 / 连不上 | Windows 端照常工作，恢复后 NAS 执行 `git pull --rebase` 即可 |
| 误删文件 | `git checkout -- <file>` 恢复；已提交的用 `git revert`，不要 `reset --hard` 后强推 |
| 只想看 NAS 文件 | 用 `ssh` + `cat`/`sed`，不要通过 SMB 直接编辑 git 仓库（权限与锁不可靠） |

## 6. 禁止事项

1. **禁止 `git push --force` 到 `main`**（会抹掉另一端提交）。
2. 禁止在 NAS 与 Windows 同时修改同一文件后各自提交。
3. 数据库迁移、生产部署、删除数据仍按 `.clinerules` 走确认流程，不因“同步”而放宽。
4. `.wrangler/`、`*.sql` 备份、`.env` 已被 `.gitignore` 忽略，不会跨端同步，也不要提交。
